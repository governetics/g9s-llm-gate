# D-002 — Контракт llm-gate с панелью governetics (Path A)

**Дата:** 2026-11-04 · **Статус:** ACTIVE · **Сессии:** design 261104-01 (план),
impl 261104-01 (фаза 2; хранятся в доме проекта верстака)

## Контекст

Панель governetics разворачивает compose-шаблон операторского проекта (Path A): читает
`x-g9s-config`, заводит ключи на шаге Configure, переписывает `image` на дайджест при
деплое, сама добавляет `env_file`/тома доставки для объявленных ключей. Требование
проекта: **один и тот же файл** работает локально (`docker compose --env-file .env`) и в
панели без правок. Правила контракта — наследие g9s-mediapump D-002: fail-loud
подстановки обязательных ключей, у каждого ключа consumer, секреты `visibility:
invisible`, никакой ручной записи каналов доставки (`env_file`/`volumes`) в шаблоне.
Контракт этого проекта фиксирует, как правила легли на LiteLLM+PostgreSQL.

## Решение

**(а) `x-g9s-config` — пять ключей**, по одному consumer-сервису на назначение
(`db` потребляет только пароль postgres):

| Ключ | Consumers | Visibility |
|---|---|---|
| `LLM_GATE_BIND` | litellm | — |
| `LLM_GATE_PORT` | litellm | — |
| `LLM_GATE_MASTER_KEY` | litellm | invisible |
| `LLM_GATE_SALT_KEY` | litellm | invisible |
| `LLM_GATE_POSTGRES_PASSWORD` | litellm, db | invisible |

**(б) Fail-loud подстановки.** Каждый обязательный ключ — `${KEY:?…}`: пустое значение
(панель пропускает пустое через completeness-чек) роняет `up` с текстом `<ключ> is not
set`, а не публикует сервис на всех адресах/случайном порту/сломанном DSN.

**(в) Маппинг на имена образа — через `environment:`**, не через панельный `env_file`:
панель добавляет `env_file` для своих ключей, и `env_precedence` затенил бы явный
маппинг (`LITELLM_MASTER_KEY`, `LITELLM_SALT_KEY`, `DATABASE_URL`, `STORE_MODEL_IN_DB`).

**(г) Policy-YAML — `configs.content`.** Routing-политика живёт в теле шаблона:
самодостаточно в обоих контурах, без файлов рядом. В контенте нет `$` — compose
интерполирует содержимое configs, а панель стабит `${…}` до парсинга. Compose не
пересоздаёт контейнер при изменении только контента конфига — пересоздание обеспечивает
hash-лейбл `llmgate.policy-sha256` (16 hex sha256 контента; соответствие пинится
тестом).

**(д) `db` без host-портов** — БД отвечает только в compose-сети; наружу смотрит
исключительно litellm на `BIND:PORT`.

**(е) `restart: unless-stopped` вместо `depends_on: condition: service_healthy`.**
litellm, стартующий раньше готовности db, падает и возвращается restart-политикой — та
же механика покрывает и старт, и любые сбои в эксплуатации; `start_period` 300 с даёт
место первичным Prisma-миграциям.

**(ж) Пины минорных тегов** — `v1.108.0` / `16.15`, никогда `latest`: обновление LiteLLM
тянет Prisma-миграции и идёт процедурой «пин → бэкап → смена → проверка».

## Отвергнутые альтернативы

- **Host-порт у `db`** — отвергнуто: БД не должна отвечать за пределами compose-сети;
  наружу опубликован только шлюз.
- **Ручные каналы доставки секретов** (вписанные в шаблон `env_file`/`volumes`) —
  отвергнуто: панель доставляет значения сама по декларации ключей в `x-g9s-config`
  (правило Path A).
- **`depends_on` с `condition: service_healthy`** — отвергнуто: условная зависимость
  покрывает только первичный старт; возврат litellm при поздней недоступности db в
  эксплуатации всё равно лежит на restart-политике — принята одна механика вместо двух.
- **Отдельные шаблоны для контуров** — отвергнуто: два файла = двойная книга топологии;
  единство шаблона — решение [D-001](D-001-artefakt-llm-gate.md), здесь оно держится
  контрактом (расходятся только значения ключей).

## Последствия

- Парсер панели принял шаблон: живой прогон тестов с `GOVERNETICS_ROOT` (после фикса —
  сравнение сервисов как множеств, `sorted()`) и живой Deploy 2026-11-04 (`converged`,
  liveliness 200 по HTTPS). **Document order сервисов — не контракт:** парсер отдаёт
  сервисы в порядке объявления, тесты не должны пинить порядок.
- Панель проверяет заполненность ключей, но не их семантику: master key без префикса
  `sk-` проходит Configure/Deploy и молча ломает UI-логин — якорь в README.
- `visibility: invisible` прячет значение только в UI панели; `docker inspect` на узле
  его показывает — предел платформы.

## Открытое

- Изменение policy-YAML через панель (redeploy с новым hash-лейблом) — приёмка фазы 3.
- Backup/restore живьём на ноде (`DB_CONTAINER` панели отличается от локального
  умолчания) — приёмка фазы 3.
- L2-прогон панельного парсера требует checkout governetics (`GOVERNETICS_ROOT`); без
  него тест skip — штатно, но панельные гейты (env_precedence, bind_mounts, tag-pattern)
  локальным прогоном не покрыты.
